# Command Mode: spoken phrases that act instead of transcribe

**Status**: Draft
**Type**: Feature (new pipeline branch, new session state, new host command)
**Scope**: `apps/whispering/src/lib/`, `apps/whispering/src/routes/(app)/(config)/settings/dictation/`, `apps/epicenter/src-tauri/`

## Problem

Every utterance Whispering hears becomes text. There is no way to say something
to the app rather than through it. Two moments need that:

- A delivered transcript is wrong and the hands are still off the keyboard.
- A voice-activated session is armed and the only way to disarm it is a hotkey.

Command Mode gives a small fixed set of spoken phrases that run an action and
deliver nothing.

## What the pipeline forces

The recorder shape decides most of this design, so it comes first.

`stopManualRecording` calls `processRecordingPipeline`. The transcript exists
only because the stop already happened. Under whole-utterance matching, in
manual mode:

- "stop recording" is structurally a no-op. The stop is what produced the phrase.
- "cancel recording" cannot abort a live capture. The audio is captured, the row
  is written, transcription has already run and been paid for.
- pause and resume have no referent at all between manual utterances.

VAD is the only mode where session-control phrases have meaning, because
`onSpeechEnd` runs the pipeline per utterance while the session stays armed
(`operations/recording.ts`).

The same constraint prices out text shaping. Saying "new paragraph" as its own
isolated utterance, with a pause on each side, is slower than pressing Enter.
The hands-free win exists only mid-stream, inside a longer utterance, and
mid-stream matching has unbounded false positives with no boundary rule that
fixes them ("he said scratch that idea and moved on").

What survives whole-utterance matching cleanly is a third category: phrases
acting on **prior output** or on **session state**. That is what v1 ships.

## Decision: a deterministic matcher before Polish

```
transcribeAndPersist
  -> matchCommand(transcript)
       |- match     -> run effect, no Polish, no delivery, return
       |- no match  -> Polish -> expandSnippets -> deliver   (unchanged)
```

Three placements were considered.

**Prompt block, like Dictionary (rejected).** Ask the model to classify the
utterance as command or content. A misclassification is silent, and the feature
would depend on Polish being on, which the user controls. Same objection that
kept Snippets out of the prompt (ADR-0099).

**Deterministic, after Polish (rejected).** This is where Snippets sits, and for
Snippets it is right: its failure mode is a visible literal trigger in the
delivered text. Command Mode inverts that. Polish rewrites "scratch that" into
prose, so the phrase would arrive at the matcher already destroyed, and the
failure would be an unrecognized command that silently ships as text.

**Deterministic, before Polish (chosen).** The matcher sees exactly what was
said. Its failure mode is a phrase that does not match, which delivers as
ordinary text: visible and recoverable, the same standard Snippets is held to.

The asymmetry with Snippets is the point. Snippets act on text that is shipping.
Commands intercept text that is not.

## The matcher

`operations/match-command.ts`, pure and total, no app argument, the same shape
as `expand-snippets.ts`:

```ts
export type VoiceCommandId = 'scratchThat' | 'stopListening';
export function matchCommand(text: string): VoiceCommandId | null;
```

The phrase table is a constant in the module, not user data. Snippets are the
user's content; commands are app behavior, and a user-editable phrase table
buys nothing in v1.

Matching is normalized whole-utterance equality. Whisper reliably appends a full
stop, so "Scratch that." must reach the table as `scratch that`.
`expandSnippets` needs no normalization because its word-boundary regex absorbs
punctuation mid-text; an equality check does not.

The normalization is a rule, not a description, because the interesting cases
are decided by its exact order:

1. Trim surrounding whitespace.
2. Strip runs of `\p{P}` and `\p{S}` from **both ends only**, repeatedly:
   `/^[\p{P}\p{S}]+|[\p{P}\p{S}]+$/gu`.
3. Collapse internal whitespace runs to a single space.
4. `toLowerCase()`.

Punctuation inside the phrase survives, which settles the ambiguous cases:
"scratch that!" and "...scratch that..." both match; "scratch, that" does not,
because the comma is internal and no table entry contains it. A phrase needing
an internal apostrophe would have to spell it in the table.

Phrases for v1:

| Phrase | Command |
| --- | --- |
| "scratch that", "undo that" | `scratchThat` |
| "stop listening" | `stopListening` |

## Guards

**Dictation only.** The branch runs only when `isDictation` is true, the flag
the pipeline already derives from `deliverySource`. A transcribed meeting
recording containing the words "stop listening" must never fire anything.

**Applicable only.** `isDictation` is true in manual mode as well as VAD, so a
global dictation guard is not enough. Saying "stop listening" during a manual
dictation would match, run a no-op, and return early, swallowing the utterance:
no text and no action, the worst outcome in the whole design.

So a match is not sufficient to branch. The matcher stays pure and the pipeline
asks a second question before taking the branch:

```ts
function commandApplies(id: VoiceCommandId): boolean;
```

Applicable means the command can actually act, and it means that uniformly.
`stopListening` applies only while `isVadRecordingActive()`. `scratchThat`
applies only while something undoable is held, which it asks with a peek that
does not consume the record.

An earlier draft of this design exempted `scratchThat`, on the reasoning that it
reports its own "nothing to undo" case. The shipped defaults break that
reasoning: `outputTranscriptionCursor` is off and `outputTranscriptionClipboard`
is on, so the default sink never touches the keyboard, nothing is ever undoable,
and every "scratch that" on a fresh install would be swallowed with no text and
no action. The exemption turned the worst outcome in this design into the
primary path, so there is no exemption.

A matched but inapplicable command falls through to normal delivery. The words
"stop listening" arrive as text, which is visible and recoverable, the standard
the placement decision already set. It also removes the silent no-op from
`stopListening`: the phrase either disarms a live session or types itself.

**Opt in.** A new `commandModeEnabled` boolean in the workspace kv, default
off. Turning the dictated words "scratch that" into a destructive keystroke is
not something an existing user should discover by accident.

**The recordings row stays.** It is created before transcription runs, so a
command utterance is already in history by the time it is known to be a
command. Keeping it costs nothing and gives an audit trail for the case that
will need one: a misfire.

**The branch returns before everything downstream.** No Polish, no snippet
expansion, no `polishedTranscript` write, no `transcriptionComplete` sound, no
delivery. The sound is the receipt for text arriving somewhere, and no text
arrived.

**The held-delivery write is dictation-only, and every delivery clears first.**
A file import delivers text through the same sink, but "scratch that" after
importing a meeting recording would target a paste the user never dictated. Only
the `isDictation` path records what it delivered. Recording is not enough on its
own, though: see "Every delivery invalidates the last one" below.

## scratchThat

Sends N backspaces, where N is the **grapheme** count of the last delivered
text. Grapheme count, not `text.length`: one backspace deletes one grapheme
cluster, so a UTF-16 length would overshoot on an emoji or a combining mark and
eat the user's own words. `Intl.Segmenter` gives the right number.

### Held state

`state/last-delivery.svelte.ts` holds one record or nothing:

```ts
type LastDelivery = {
	text: string;
	sinkKind: SinkKind;
	reach: DeliveryReach;
	pressedEnter: boolean;
};
```

Written by the pipeline after a successful delivery, read and cleared by
`scratchThat`. Consumed once: a second "scratch that" finds nothing held rather
than deleting another paste's worth of characters.

Every field is load-bearing. `text` gives the count, and being empty is itself
disqualifying; `sinkKind`, `reach` and `pressedEnter` decide whether a backspace
can reach anything at all.

The module also exposes a non-consuming `canUndo()`, because applicability has to
ask whether an undo is possible before the pipeline commits to the command
branch, and asking must not destroy the thing it is asking about.

**`DeliveryOutcome` has to carry the sink kind and the Enter.** The pipeline
sees `deliveredText` and the reach, and nothing else. Which sink ran is decided
inside `delivery.ts` by `resolveSettingsSink` and never leaves it, and whether an
Enter followed the paste is known only to the cursor sink, so the pipeline can
record neither today. `Sink.deliver` returns `{ reach, pressedEnter }`, and the
outcome carries both facts on:

```ts
export type DeliveryOutcome = {
	reach: DeliveryReach;
	sinkKind: SinkKind;
	pressedEnter: boolean;
};
```

`deliverToSink` already holds `sink.kind`, so both `deliverTranscriptionResult`
and `deliverRecipeResult` get it for free. The alternative, re-deriving the sink
from settings at the pipeline, would duplicate `resolveSettingsSink` and drift
from it the first time the toggles change shape.

This makes `SinkKind` part of `sink.ts`'s exported surface, which it is not
today. That is intentional: the kind is now an answer delivery gives its
callers, not a private detail.

### Where undo cannot reach

A record is undoable only when its text is non-empty and it was a cursor sink
with a clean `output` reach and no Enter after it. `clipboardSink` and
`ledgerSink` never touch the keyboard, and a cursor write that fell back to
`reach: 'clipboard'` did not paste either. In those cases the command reports
that there is nothing at the cursor to undo.

This is a capability constraint, not the best-effort risk being accepted. The
accepted risk lives inside a successful paste: the target application may have
transformed the text after it landed (autocorrect, a markdown editor, a field
mask), so the count can be wrong. There is no time window and no warning, the
same trade Wispr Flow makes.

The state is session-scoped and dies with the process, which is correct: a
transcript delivered before a restart is not something a backspace can find its
way back to.

### Every delivery invalidates the last one

Recording only on the dictation path is not enough on its own. A file import, a
recordings row's Transcribe button, and a recipe run all paste through the same
sink, and none of them is a dictation. If they leave an older record in place, a
later "scratch that" counts graphemes from a dictation while the cursor holds
something else entirely, and backspaces into text Whispering did not deliver.

So `deliverToSink` clears the held record on every delivery, and the dictation
pipeline records the new one straight after. One clear in the shared path covers
every caller, including ones added later; per-call-site clears would not.

### Known limitation: overlapping VAD utterances

`onSpeechEnd` is fire and forget, so in a voice-activated session the pipeline
for one utterance can start before the previous one has delivered. A short
command transcribes faster than a long sentence, so saying a sentence and then
"scratch that" immediately can run the undo before the sentence lands. The undo
then acts on an older record, or finds nothing and refuses.

Not fixed in v1. Fixing it means serializing pipeline runs per session, which
changes the recorder's contract and is well outside this feature.

### Cap

At most 2000 backspaces, matching the cap Snippets already puts on replacement
length. Above it the command refuses rather than partially deleting, because a
five-minute dictation would otherwise fire thousands of synthetic keystrokes
into whatever holds focus.

## stopListening

Calls the existing `stopVadRecording(app)`. The applicability guard above has
already established a live session, so this reaches a real teardown every time
it runs; `stopVadRecording`'s own `if (!isVadRecordingActive()) return;` remains
as the race backstop it already was.

## The host command

No backspace primitive exists. `services.text` exposes `writeToCursor`,
`simulateEnterKeystroke` and `simulateCopyKeystroke` and nothing else. The
`enigo` crate is already a dependency of `apps/epicenter/src-tauri`, and
`simulate_enter_keystroke` in `delivery.rs` is the template.

Footprint:

- `delivery.rs`: `simulate_backspaces(count: u32)`, a `Key::Backspace` click loop.
- `command_names.rs`: add `"simulate_backspaces"` to `COMMANDS`.
- `lib.rs`: import it and add it to `collect_commands![]`.
- `capabilities/trusted-whispering-native-development.json` and
  `-production.json`: add `"allow-simulate-backspaces"`.
- Both generated binding targets regenerate from the export step:
  `apps/whispering/src/lib/tauri/bindings.gen.ts` and
  `apps/epicenter/src/ui/bindings.gen.ts`. Each carries the whole API; what a
  window may call is decided by its capability file, not by its bindings copy.

The crate's own tests check the capability files and the generated bindings
against `COMMANDS`, so a half-finished wiring fails there rather than at
runtime.

`TextService` then gains `simulateBackspaces(count)` beside
`simulateEnterKeystroke`, same `Result` shape.

## Settings and UI

One toggle, `commandModeEnabled`, on the existing `settings/dictation` page,
default off, with the fixed phrase list rendered read-only underneath it so the
phrases are discoverable without documentation.

The dictation pill needs no new state, but it does need one call. The pipeline
marks the lifecycle `transcribing` on the way in, and the command branch is the
one exit that never reaches a terminal marker, so it must reset the lifecycle
before returning. Without that the pill spins on "Transcribing" indefinitely
after every command. A command delivers no text, so `reset` is the right
terminal call: there is no outcome to show.

## Failure handling

Nothing here is a dictation failure. The posture follows the reduced-reach rule
the codebase already holds (ADR-0039).

| Situation | Behavior |
| --- | --- |
| Command mode off, or no phrase match | No branch taken; the transcript delivers normally |
| `scratchThat` with nothing undoable held | Not applicable, so no branch: the phrase delivers as ordinary text |
| `scratchThat` finds the record gone between the applicability check and the take | `report.info`, no keystrokes. A defensive path, not the common one |
| The held text is longer than the cap | `report.info`, no keystrokes. Checked in TypeScript against a constant mirroring the host's, because the host's refusal arrives as the same opaque error as any other failure and would otherwise read as an error |
| The backspace call fails | `report.error`, and the held state is cleared anyway: after a partial delete the count no longer describes the screen |
| `stopListening` with no VAD session | Not applicable, so no branch: the phrase delivers as ordinary text |

  normalization rule (trailing full stop, "scratch that!", "...scratch that...",
  capitalization, surrounding and internal whitespace), the internal-punctuation
  case that must not match ("scratch, that"), near misses that must not match
  ("scratch that idea", "please stop listening"), and empty input.
- Applicability: `stopListening` matched with no live VAD session falls through
  to delivery rather than branching, and `scratchThat` always branches.
- `match-command-pipeline.test.ts`, mirroring `expand-snippets-pipeline.test.ts`:
  the property that made "before Polish" right, which is that a phrase Polish
  would have reworded still matches because the matcher never sees polished
  text.
- Held-delivery state: cursor-and-output is undoable, every other combination is
  not, and the record is consumed once.
- Grapheme counting: an emoji and a combining mark each count as one backspace.
- Manual verification in the Tauri shell, as the Snippets seam was verified. The
  keystroke path cannot run under `bun test`.

## Files

New: `operations/match-command.ts` (pure matching),
`operations/run-voice-command.ts` (`commandApplies` and the effect dispatch),
`state/last-delivery.svelte.ts`, and their tests.

The effects live beside the matcher rather than inside `pipeline.ts` because the
pipeline is already the longest operation in the app and the dispatch grows with
every future command. The matcher stays pure and app-free; the runner is the
half that touches `app`.

Edited: `operations/pipeline.ts` (one branch, one write),
`operations/delivery-reach.ts` (`DeliveryOutcome` grows `sinkKind`),
`operations/sink.ts` (export `SinkKind`), `operations/delivery.ts` (return it),
`services/text/types.ts`, `services/text/index.tauri.ts`,
`workspace/index.ts` (one boolean),
`routes/(app)/(config)/settings/dictation/+page.svelte`.

## Deferred

**pause and resume.** They are the only commands that would add held mid-session
state, and their cost profile is the worst of the set: a paused VAD session must
keep transcribing every utterance, because transcription is the only way to hear
"resume". So a paused session keeps spending cloud transcription calls and keeps
writing rows nobody asked for. Their one advantage over `stopListening` is
coming back by voice. Revisit once the seam exists.

**Text shaping** ("new paragraph", "comma", "capitalize"). Worthless as isolated
utterances, as argued above.

**Mid-stream matching.** The prerequisite for text shaping, and the source of
unbounded false positives. If the phrase table ever outgrows a fixed list, the
migration target is the existing `commands.ts` registry, whose own docstring
already names voice as a trigger backend. That registry is keyboard-shaped
today (`on: ShortcutEventState[]` has no voice analogue, and `reach` means
global-versus-focused hotkey scope), so reuse is a reshaping job, not free.
